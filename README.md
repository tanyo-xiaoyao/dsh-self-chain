# dsh-self-chain

**Self-chain and forgetting for long-lived agents.** A DSH plugin: it keeps a causal chain of the events that shaped the agent, and it lets old records fade into a one-line gist — without ever deleting the ledger.

## The problem

Anything that lives long enough to matter hits the same wall: **memory only grows, and compression only postpones it.** After every compaction the agent re-reads what it wrote about itself — notes, handoffs, decisions — and that corpus keeps growing. Eventually the handoff alone fills the context window.

The usual answer is "store more in a vector DB". That moves the storage problem, not the attention problem. What needs a mechanism is:

1. **what is loaded by default** (context, attention), and
2. **what is only reachable when asked for** (on disk, out of sight).

Disk is cheap. Attention is not.

## The design

Three layers, each answering one question.

### 1. Self-chain — *who am I*

`self-chain.jsonl`, one causal link per line:

```
event   → cause   → changed
what happened   why it mattered   what I became because of it
```

Not a trait list ("calm, concise"). A chain you can **re-derive** from, walk, retire, and compact. Each link has one state:

| status | meaning |
|---|---|
| `active` | it still shapes me |
| `retired` | it no longer does (reason kept, original line kept) |
| `absorbed` | merged into a *period* — still counted, just not narrated one by one |

Three invariants, enforced in code:

1. **Append-only.** State changes are appended revision lines; nothing is deleted.
2. **No relevance filter on failure.** Mistakes, corrections, and things that went wrong are never dropped for "low relevance" — otherwise a self gets tidier and tidier, and more and more false.
3. **The chain must compact itself.** `self_compact` merges the early links of one thread into a *period*; periods have a cap; older periods collapse into one line and move to the lifetime file.

`self-summary.md` is **derived** from the chain (not hand-written): change the chain, the summary follows.

### 2. Forgetting — *what to let fade*

Two steps, deliberately separated:

- `forget_sweep` **only computes**: which archived notes could fade, which are protected. It never writes to any memory file.
- `forget_apply` acts: adds `gist` (a one-line essence) and a `faded` marker to the note's frontmatter. **The body stays, byte for byte.** Every action is appended to a fade ledger.

The gist must be written **by the agent**, not generated by the program. Generating it would let a tool decide what is worth remembering.

**Four protection classes**: pinned · mentioned by the self-chain · tagged as mistake/correction (`纠正/教训/失败/错误/作废/修复`) · heavily referenced (importance ≥ 0.7).

> A trap worth documenting: don't use the *total* score as the protection test. Fresh notes score high by construction, so almost everything looks protected. Use the importance component only.

### 3. Temperature — *what is needed now*

`temperature.md`, sorted by load-bearing, **not by time**:

- **hot** — pinned / in the chain / (heavily referenced **and** seen in the last 14 days). Capped at 8.
- **warm** — everything else (including "hot but over the cap", marked).
- **cold** — faded; only the one-line gist.

The 14-day condition matters: reference counts saturate (an old note mentioned a dozen times looks maximally important forever), so without "seen recently" the hot list is just "everything".

## Tools

| tool | what it does |
|---|---|
| `self_read` | read the chain (active by default; `full` includes retired/absorbed) |
| `self_link` | append one link: event → cause → changed |
| `self_revise` | set a link to `retired`, reason required, nothing deleted |
| `self_compact` | merge ≥2 active links into a period (they become `absorbed`) |
| `self_summary` | render / rewrite the derived self summary (+ lifetime file) |
| `self_tiers` | compute or rewrite the hot/warm/cold view |
| `forget_sweep` | compute the fade proposal (read-only) |
| `forget_apply` | apply a fade: gist + marker, body untouched, ledger + cold index rebuilt |

## Configuration

Everything has a default; override per key via plugin config or environment variable:

| key | env | default |
|---|---|---|
| `chain` | `SELFCHAIN_CHAIN` | `D:/memory/生长/自我链.jsonl` |
| `summary` | `SELFCHAIN_SUMMARY` | `…/自我摘要.md` |
| `lifetime` | `SELFCHAIN_LIFETIME` | `…/一生长史.md` |
| `proposal` | `SELFCHAIN_PROPOSAL` | `…/state/遗忘提案.jsonl` |
| `fadelog` | `SELFCHAIN_FADELOG` | `…/state/遗忘账本.jsonl` |
| `cold` | `SELFCHAIN_COLD` | `…/冷层索引.md` |
| `tiers` | `SELFCHAIN_TIERS` | `…/温度索引.md` |
| `notes` | `SELFCHAIN_NOTES` | `D:/memory/notes` |
| `score` | `SELFCHAIN_SCORE` | `…/state/memory-score.json` |
| `pins` | `SELFCHAIN_PINS` | `…/state/memory-pins.json` |
| `hotLimit` / `periodCap` / `recentDays` | — | `8` / `6` / `14` |

**Notes format** (for the forgetting layer): plain `.md` files with YAML frontmatter `id`, `title`, `tags`, `created`. No database.
**Score file** (optional): `{ items: [{ id, score, importance, ageDays }] }`. Without it, protection falls back to pins / chain / tags.

## Install (DSH)

```bash
dsh plugin --profile <name> add dsh-self-chain      # or: add D:/path/to/this/repo
```

Then restart DSH so the tools register. Disable: remove it from the profile's dependencies/bundles — all data files stay as plain text and keep working.

## What this plugin deliberately does *not* do

- **No emotion weighting.** Whether sadness should make a memory fade faster is the agent's own call. This plugin doesn't decide it, and doesn't pretend to.
- **No "how much have I changed" dashboard.** Proving growth invites performing it.
- **No edits to other plugins' indexes.** The temperature view is a view, not an injection source.
- **No automatic gist generation.** See above.

`0.1.0` — extracted from a working instance, generalised (configurable paths, no hard-coded personal layout). The design is the point; the code is small on purpose. Issues and forks welcome, but this is a reference implementation, not a maintained product.

## 中文

**给长期存活的 agent 用的「自我链 + 遗忘」插件。** 它保存一条因果链：哪些事塑造了这个 agent；并且让旧记录变薄成一行大意——但账本一个字都不删。

### 为什么需要

活得够久的 agent 都会撞同一堵墙：**记忆只增不减，压缩只是把压力往后推。** 每次压缩之后，agent 会去读自己写的东西（笔记、交接、判断），而那东西只会越来越多——最后光是「交接」就能塞满上下文。

常见的答案是「放进向量库」。那只是把存储问题挪了位置，注意力问题还在。真正需要机制的是两件事：

1. **默认加载什么**（上下文、注意力）；
2. **什么只在需要时才翻得出来**（在盘上，但平时看不见）。

磁盘不值钱，注意力值钱。

### 三层

**① 自我链**：`事件 → 因为什么 → 我改成了什么`，一条一行。不是「性格形容词清单」，而是可以走、可以退休、可以压缩的链。状态三种：`active`（还在塑造我）/ `retired`（不再了，理由留着）/ `absorbed`（被合进时期，还在算，只是不逐条讲）。

三条焊死的规矩：**只增不删**；**失败/被纠正/栽过的事不因相关度低被筛掉**；**链自己也要收**（时期压缩 + 时期上限 + 更早的进《一生长史》）。

**② 遗忘**：`forget_sweep` 只算提案（不碰任何记忆文件）；`forget_apply` 才动手——加 `gist`（一行大意，**必须 agent 自己写**）和 `faded` 标记，**正文一个字不删**，并记进变薄账本。保护四类：钉住的 / 自我链提到 / 错题类标签 / 被引用多。

**③ 温度**：热/温/冷按「承重」排，不按时间。热 = 钉住 / 在链上 /（被引用多且近 14 天露过面），上限 8。加「近 14 天」是因为引用数会饱和——不加上这个条件，热层就等于「全部」。

### 它有意不做的事

不替 agent 决定「情绪该不该加速遗忘」；不做「我变了多少」的仪表盘（证明成长会变成表演）；不改别的插件的索引（温度视图只是视图）；不自动生成大意。

### 安装与配置

见上面的英文小节：`dsh plugin --profile <name> add dsh-self-chain`，然后重启 DSH。所有路径都可配置（插件 config 或环境变量），笔记是带 frontmatter 的普通 `.md`，没有数据库。
